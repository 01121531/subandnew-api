# 邮箱管理与独立操作员

## 使用范围

本模块用于管理员保管和分配已获授权使用的邮箱凭据，以及操作员提交截图后的人工审核。不会登录 Google、读取邮件、访问第三方验证码网站或自动轮换远端凭据。

控制台入口为 `/mailbox-management`，独立操作员入口为 `/mailbox/sign-in`。操作员会话不复用控制台或供货商门户会话，禁止公开注册。仅在 HTTPS 下使用，独立会话 Cookie 为 HttpOnly、Secure、SameSite=Strict，有效期 12 小时。

## 权限与操作

超级管理员拥有全部权限，普通管理员必须显式获授 `mailbox_management` 下的权限：

| 权限 | 用途 |
| --- | --- |
| view | 查看共享邮箱池和截图 |
| manage | 校验并导入邮箱 |
| assign | 分配、回收和改派 |
| review | 查看提交、通过或退回 |
| credentials | 按需读取邮箱密码、当前验证码或开号卡片资料 |
| operators | 创建、编辑、停用操作员，重置密码和撤销会话 |
| audit | 查看操作记录 |

本模块不使用实例范围和账号快照字段权限。列表永不返回邮箱密码或 2FA 原始密钥。操作员只有当前有效分配的凭据读取权，审核通过后立即失去该权限；停用操作员或重置密码会撤销其全部会话。

邮箱流程：未分配 → 待处理 → 待审核 → 已通过 / 已退回。退回必须填写原因；操作员重新提交生成新的历史记录，不覆盖旧提交。回收和改派不会把前任截图转交给新操作员。前任仍可访问本人提交历史，但不能继续读取被回收邮箱的凭据。

## 退款与开号

邮箱池分为固定的 `refund`（退款）和 `opening`（开号）两类。退款包含邮箱、密码和 2FA；开号另附一组卡号与有效期，不建立独立卡片池，不接收 CVV。类型创建后不能更改，两池不提供转移或同步。

两池分别对规范化邮箱地址去重。同一个邮箱可以在两池各自存在，但记录 ID、凭据、分配、提交和截图始终独立。操作员共用本站账号，仅查看每类中分配给自己的记录。

升级会将已有邮箱归入退款，保留原 ID、凭据和全部历史记录。旧客户端未传 `account_type` 时按退款处理；新客户端导入、列表、分配和历史查询使用 `refund` 或 `opening`。同一批分配不能混入另一类型的记录。

## 导入格式

每批最多 1,000 行，先预览校验，再确认导入。任何行无效时整批不写入；重复邮箱不覆盖旧凭据。请使用受控测试数据验证，不把真实密码和密钥粘贴到工单或日志中。

- 退款：固定三列，顺序为邮箱、密码、2FA。
- 开号：固定五列，顺序为邮箱、密码、2FA、卡号、有效期。有效期使用 `MM/YY`，不接受已过期卡片。
- 文本：每行按制表符或 `----` 分隔，不填写表头。
- CSV / XLSX：使用界面说明中的列标题。Excel 凭据列应设为文本，不使用公式；卡号数值单元格会被拒绝，以防长卡号精度已丢失。CSV 应直接作为文本生成，不经电子表格数值转换。
- 卡号接受空格或连字符分隔，规范化后校验位数和校验位。这只能校验格式，不能确认卡片有效性或使用授权。
- 额外列及 CVV 列会使整批校验失败，不会静默忽略。不要把 CVV 放入名称、密码、备注或截图。
- 密码保留原有空格，不自动裁剪。
- 2FA 接受 Base32 密钥或 `otpauth://totp` 链接。普通密钥默认 SHA-1、六位、30 秒；链接仅接受支持的 TOTP 参数，不接受 HOTP。

导入预览仅显示邮箱、行号、卡号后四位和安全错误码，不回显密码、密钥或完整卡号。操作员按需查看密码、动态验证码及开号卡片资料；验证码由服务端时间生成，请保证节点时钟准确同步。原始密钥永不向操作员返回。

以下仅为格式测试数据，不是可用邮箱或支付资料。退款文本示例：

```text
demo@example.test----DemoPass!2026----JBSWY3DPEHPK3PXP
```

开号文本示例（无 CVV 列）：

```text
demo@example.test----DemoPass!2026----JBSWY3DPEHPK3PXP----4242424242424242----12/99
```

## 卡片数据保护

卡号与有效期使用独立关联数据和现有主密钥加密，普通列表只展示卡号后四位。完整资料仅通过受权限保护的凭据读取接口返回，审核通过、回收、改派及停用会撤销操作员的后续访问。管理员的读取仍要求 `credentials` 权限。

密码和卡片资料单次显示最多 60 秒；关闭详情、切换类型或页面隐藏时清理显示内容，再次查看需重新请求并校验权限。该限制不能撤回已经被看到或复制的内容，也不替代远端卡片冻结或密码轮换。

本站不导入、不存储或交付 CVV，实际支付时应在支付服务的安全页面填写。截图提交前须遮挡完整卡号及 CVV；图片格式和元数据校验不等于敏感信息识别，仍需上传者脱敏和人工审核。

**加密保存不等于已完成 PCI DSS 合规认证。** 部署方应评估实际支付场景、卡片数据保留必要性、访问授权、密钥管理及备份范围，避免无限期积累不再需要的资料。数据库备份同样包含卡片密文，必须限制访问、加密保护并明确保留和销毁周期。禁止代理、APM、请求追踪或会话回放采集导入和凭据接口正文。

## 私有图片存储

配置环境变量 `MAILBOX_ATTACHMENT_DIR` 指向独立持久化目录；未配置时使用进程工作目录下的 `data/mailbox-attachments`。不要放到 Web 静态目录，也不要通过 Nginx alias、对象存储公共桶或 CDN 公开该目录。

部署要求：

1. 服务用户须有读写权限，其他无关用户不能读取目录。容器重建不得丢失该持久化卷。
2. 多节点必须挂载同一份共享私有存储，并使用相同的加密主密钥和版本。节点本地临时目录不能用于多节点正式环境。
3. 沿用 `MANAGED_INSTANCE_SECRET_KEY` 主密钥体系。邮箱凭据使用独立关联数据加密；丢失密钥后无法解密已有数据。不要直接替换密钥冒充完成了轮换，应遵循现有密钥迁移流程。
4. **数据库、图片目录和主密钥必须一并纳入备份与恢复演练**，密钥应在独立安全位置保存。仅备份数据库不能恢复截图。限制备份访问权限并加密备份。
5. 上传链路需允许单张 10MB 图片及 multipart 开销。反向代理请求体上限应大于 11MB，导入文件接口还需要相应的 12MB 请求体空间。

单次提交包含 1～5 张 PNG、JPEG 或 WebP 图片，每张原文件最多 10MB。后端按真实文件内容解析，限制图像尺寸与像素数，并重新编码移除元数据；随机文件名不含邮箱或原始文件名。图片通过鉴权 API 读取，没有公开静态 URL。

已提交图片从提交时间起保留 365 天，未提交附件保留 24 小时。Master 在启动后及每小时执行过期清理，删除图片后保留提交、审核和清理记录。图片即使尚未物理清理，超过保留期限也不能继续读取。备份副本的保留期限需由部署方另外配置，应用清理不会删除离线备份。

## 安全边界

密码、验证码、密钥、完整卡号、有效期、请求正文和图片内容不进入应用审计。反向代理/APM 同样不得采集这些接口的请求体或响应体。审计保留操作者、对象、类型、动作、结果、时间和来源 IP。

已经展示、复制或下载的信息无法追溯撤回。若需要彻底撤销对 Google 邮箱的访问，应在 Google 侧轮换密码及 2FA 密钥；本站的回收、改派和审核通过只撤销后续本站凭据读取权。

操作员忘记本站密码时，由获授权的管理员重置；本站密码不是 Google 邮箱密码。
