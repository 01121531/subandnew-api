# 邮箱管理与独立操作员

## 使用范围

本模块用于管理员保管和分配已获授权使用的邮箱凭据，以及操作员提交截图后的人工审核。不会登录 Google、读取邮件、访问第三方验证码网站或自动轮换远端凭据。

控制台入口为 `/mailbox-management`，独立操作员入口为 `/mailbox/sign-in`。操作员会话不复用控制台或供货商门户会话，禁止公开注册。仅在 HTTPS 下使用，独立会话 Cookie 为 HttpOnly、Secure、SameSite=Strict，有效期 12 小时。

## 权限与操作

超级管理员拥有全部权限，普通管理员必须显式获授 `mailbox_management` 下的权限：

| 权限 | 用途 |
| --- | --- |
| view | 查看共享邮箱池和截图 |
| manage | 校验并导入邮箱 |
| assign | 分配、回收和改派 |
| review | 查看提交、通过或退回 |
| credentials | 按需读取邮箱密码、当前验证码或开号卡片资料 |
| operators | 创建、编辑、停用操作员，重置密码和撤销会话 |
| audit | 查看操作记录 |

本模块不使用实例范围和账号快照字段权限。列表永不返回邮箱密码或 2FA 原始密钥。操作员只有当前有效分配的凭据读取权，审核通过后立即失去该权限；停用操作员或重置密码会撤销其全部会话。

邮箱流程：未分配 → 待处理 → 待审核 → 已通过 / 已退回。退回必须填写原因；操作员重新提交生成新的历史记录，不覆盖旧提交。回收和改派不会把前任截图转交给新操作员。前任仍可访问本人提交历史，但不能继续读取被回收邮箱的凭据。

## 退款与开号

邮箱池分为固定的 `refund`（退款）和 `opening`（开号）两类。退款包含邮箱、密码和 2FA；开号另附一组卡号与有效期，不建立独立卡片池。CVV 不作为长期资料，仅可按下述显式单节点配置临时交付。类型创建后不能更改，两池不提供转移或同步。

两池分别对规范化邮箱地址去重。同一个邮箱可以在两池各自存在，但记录 ID、凭据、分配、提交和截图始终独立。操作员共用本站账号，仅查看每类中分配给自己的记录。

升级会将已有邮箱归入退款，保留原 ID、凭据和全部历史记录。旧客户端未传 `account_type` 时按退款处理；新客户端导入、列表、分配和历史查询使用 `refund` 或 `opening`。同一批分配不能混入另一类型的记录。

## 导入格式

每批最多 1,000 行，先预览校验，再确认导入。任何行无效时整批不写入；重复邮箱不覆盖旧凭据。请使用受控测试数据验证，不把真实密码和密钥粘贴到工单或日志中。

- 退款：固定三列，顺序为邮箱、密码、2FA。
- 开号：保留五列，顺序为邮箱、密码、2FA、卡号、有效期；启用临时交付时可增加第六列 CVV。有效期使用 `MM/YY`，不接受已过期卡片。
- 文本：每行按制表符或 `----` 分隔，不填写表头。
- CSV / XLSX：使用界面说明中的列标题。Excel 凭据列应设为文本，不使用公式；卡号数值单元格会被拒绝，以防长卡号精度已丢失。CSV 应直接作为文本生成，不经电子表格数值转换。
- 卡号接受空格或连字符分隔，规范化后校验位数和校验位。这只能校验格式，不能确认卡片有效性或使用授权。
- 六列导入需要临时交付配置及管理、凭据两项权限，CVV 仅接受三位或四位数字字符串，Excel CVV 必须使用文本单元格。配置未启用或其他额外列会使整批校验失败。不要把 CVV 放入名称、密码、备注或截图。
- 密码保留原有空格，不自动裁剪。
- 2FA 接受 Base32 密钥或 `otpauth://totp` 链接。普通密钥默认 SHA-1、六位、30 秒；链接仅接受支持的 TOTP 参数，不接受 HOTP。

导入预览仅显示邮箱、行号、卡号后四位和安全错误码，不回显密码、密钥或完整卡号。操作员按需查看密码、动态验证码及开号卡片资料；验证码由服务端时间生成，请保证节点时钟准确同步。原始密钥永不向操作员返回。

以下仅为格式测试数据，不是可用邮箱或支付资料。退款文本示例：

```text
demo@example.test----DemoPass!2026----JBSWY3DPEHPK3PXP
```

开号文本示例（无 CVV 列）：

```text
demo@example.test----DemoPass!2026----JBSWY3DPEHPK3PXP----4242424242424242----12/99
```

## 卡片数据保护

卡号与有效期使用独立关联数据和现有主密钥加密，普通列表只展示卡号后四位。完整资料仅通过受权限保护的凭据读取接口返回，审核通过、回收、改派及停用会撤销操作员的后续访问。管理员的读取仍要求 `credentials` 权限。

密码和卡片资料单次显示最多 60 秒；关闭详情、切换类型或页面隐藏时清理显示内容，再次查看需重新请求并校验权限。该限制不能撤回已经被看到或复制的内容，也不替代远端卡片冻结或密码轮换。

默认不接受 CVV。显式单节点临时交付只用于实际支付授权前的短时使用，不能用于授权后留存或重复交易。截图提交前须遮挡完整卡号及 CVV；图片格式和元数据校验不等于敏感信息识别，仍需上传者脱敏和人工审核。

## Windows 悬浮助手与临时交付

Windows 10/11 x64 操作员可使用同版本 `mailbox-assistant-*-windows-amd64.zip`，完整解压后运行 EXE，无需安装 Python。使用独立操作员会话，支持类型切换、点击复制、显式粘贴截图、上下条及提交后下一条。客户端默认显示待处理和已退回任务，使用兼容参数 `status=actionable`；历史提交只读。

临时 CVV 仅在确认为单节点部署后设置 `MAILBOX_TEMP_CVV_MODE=single_node`，从节点和未启用的节点拒绝使用。**多节点不支持此交付功能，禁止在多节点设置该开关**。应用无法据此自动证明部署只有一个进程，配置与拓扑必须由部署者核对。

- 仅使用容量 10,000 条的进程内存，不写数据库、文件、Redis、普通缓存、审计正文或备份，进程重启即丢失。满容量时整批不导入。
- 从导入成功或补发成功开始计时，最长 10 分钟。初次分配绑定操作员与分配；回收、改派、停用、撤销会话、提交审核均清除未领取值。
- 管理员补发入口需要 `manage` 与 `credentials`，使用当前邮箱版本校验；接口为 `POST /api/mailbox-management/accounts/:id/temporary-cvv?account_type=opening`。响应只有有效期，不回显 CVV。
- 仅当前有效分配的开号操作员可以通过凭据接口 `kind=cvv` 原子领取一次。领取后立即删除服务端值；响应丢失不能自动重试，需要新补发。
- 客户端最多显示 60 秒且不超过交付期限，复制后立即清除显示，剪贴板最多保留 15 秒。其他敏感复制最多 30 秒，仅清除仍属于本次复制的内容。
- 含 CVV 的导入原文件及副本不得作为长期资料或备份保留。应禁止系统剪贴板历史与云同步、请求正文追踪、进程转储，评估交换文件和截图风险。超时与一次性领取不构成 PCI DSS 合规认证，参考 [PCI SSC](https://www.pcisecuritystandards.org/faqs/1280/)。

客户端会话由当前 Windows 用户 DPAPI 加密，不保存登录密码；退出、撤销或会话失效会清除本地会话。资料和截图草稿仅在内存中，折叠、最小化、锁屏或换任务清除敏感字段，普通失焦不隐藏。更多使用与许可说明见 [悬浮助手文档](../desktop/mailbox-assistant/README.md)。

**加密保存不等于已完成 PCI DSS 合规认证。** 部署方应评估实际支付场景、卡片数据保留必要性、访问授权、密钥管理及备份范围，避免无限期积累不再需要的资料。数据库备份同样包含卡片密文，必须限制访问、加密保护并明确保留和销毁周期。禁止代理、APM、请求追踪或会话回放采集导入和凭据接口正文。

## 导入示例与异常反馈（v1.2.80）

导入弹窗按当前退款/开号类型提供两行虚构文本和复制按钮，复制不会覆盖现有草稿。退款为 `邮箱----密码----2FA`，开号为 `邮箱----密码----2FA----卡号----有效期`。同样支持制表符，每批最多 1,000 条，密码保留原文。Excel 卡号必须使用文本单元格。可选六列示例仅在临时 CVV 已启用且当前管理员具备导入管理与凭据访问权限时展示，仍不得将真实 CVV 导入源文件长期保存。

网页操作端与 Windows 助手在待处理、已退回任务提供“反馈问题”，说明必填 1～2,000 字，可附 0～5 张截图；退款不提供信用卡问题。反馈与正常截图提交互斥，原截图草稿不会自动转为反馈附件。提交成功变为 `issue_pending`（异常待处理），停止凭据读取、上传和正常提交，清除未领取 CVV，并进入下一条可处理任务。结果不确定时仅核对反馈，不重放提交。

管理员从“异常反馈”标签按类型、问题、操作员、状态及邮箱查询。审核权限允许查看反馈及私有图片、回复并恢复原任务；回收还需分配权限。替换密码、2FA 或卡片还需导入管理和凭据访问权限。只替换显式提交字段，卡号和有效期需同时提供；不预填旧资料，邮箱与池类型不可更改。处理使用邮箱、分配、反馈三重版本校验，冲突需刷新。恢复后操作员重新读取最新资料，旧 CVV 不恢复，补发仍走独立入口。

回收、改派或停用操作员会将未处理反馈标为分配失效，不能恢复旧分配。原作者可查询本人反馈历史，继任操作员不能查看前任反馈或附件。反馈记录与正常审核独立，反馈截图保留 365 天，过期后保留处理结论及清理记录；未提交图片仍为 24 小时。

接口：管理端 `GET /api/mailbox-management/import-options`、`GET /issues`、`GET /issues/:id`、`POST /issues/:id/resolve`；操作员 `GET /mailbox-api/v1/issues`、`GET /issues/:id`、`POST /assignments/:id/issues`（后两项均以 `/mailbox-api/v1` 为前缀）。查询、提交与处理均传当前 `account_type`。新增 `mailbox_issues` 表，附件增加反馈关联，不修改历史提交。

反馈文字及截图不得包含密码、密钥、完整卡号或 CVV；应用不声称自动检测全部敏感内容。反馈与回复仅对获授权人员开放，审计只记录安全操作信息，不复制正文或资料。管理员修改本站保存的资料并不自动修改 Google 密码或信用卡本身。

## 私有图片存储

配置环境变量 `MAILBOX_ATTACHMENT_DIR` 指向独立持久化目录；未配置时使用进程工作目录下的 `data/mailbox-attachments`。不要放到 Web 静态目录，也不要通过 Nginx alias、对象存储公共桶或 CDN 公开该目录。

部署要求：

1. 服务用户须有读写权限，其他无关用户不能读取目录。容器重建不得丢失该持久化卷。
2. 多节点必须挂载同一份共享私有存储，并使用相同的加密主密钥和版本。节点本地临时目录不能用于多节点正式环境。
3. 沿用 `MANAGED_INSTANCE_SECRET_KEY` 主密钥体系。邮箱凭据使用独立关联数据加密；丢失密钥后无法解密已有数据。不要直接替换密钥冒充完成了轮换，应遵循现有密钥迁移流程。
4. **数据库、图片目录和主密钥必须一并纳入备份与恢复演练**，密钥应在独立安全位置保存。仅备份数据库不能恢复截图。限制备份访问权限并加密备份。
5. 上传链路需允许单张 10MB 图片及 multipart 开销。反向代理请求体上限应大于 11MB，导入文件接口还需要相应的 12MB 请求体空间。

单次提交包含 1～5 张 PNG、JPEG 或 WebP 图片，每张原文件最多 10MB。后端按真实文件内容解析，限制图像尺寸与像素数，并重新编码移除元数据；随机文件名不含邮箱或原始文件名。图片通过鉴权 API 读取，没有公开静态 URL。

已提交图片从提交时间起保留 365 天，未提交附件保留 24 小时。Master 在启动后及每小时执行过期清理，删除图片后保留提交、审核和清理记录。图片即使尚未物理清理，超过保留期限也不能继续读取。备份副本的保留期限需由部署方另外配置，应用清理不会删除离线备份。

## 安全边界

密码、验证码、密钥、完整卡号、有效期、请求正文和图片内容不进入应用审计。反向代理/APM 同样不得采集这些接口的请求体或响应体。审计保留操作者、对象、类型、动作、结果、时间和来源 IP。

已经展示、复制或下载的信息无法追溯撤回。若需要彻底撤销对 Google 邮箱的访问，应在 Google 侧轮换密码及 2FA 密钥；本站的回收、改派和审核通过只撤销后续本站凭据读取权。

操作员忘记本站密码时，由获授权的管理员重置；本站密码不是 Google 邮箱密码。
