# HUICHUAN-AI 多实例统一管理二开方案

> 文档状态：实施中 v0.2
>
> 适用项目：HUICHUAN-AI
>
> 最近更新：2026-08-07
>
> 核心决策：将 HUICHUAN-AI 收缩并扩展为独立控制平面，删除与多实例管理无关的本地网关、商业化和实验功能，统一纳管多个 New API 与 Sub2API 实例；首版只做管理与观测，不让业务请求绕行控制平面。

## 0. 执行摘要

本次二开的目标不是把多个项目的数据表合并成一个大库，也不是把远端实例当作普通渠道，而是在 HUICHUAN-AI 中新增“实例中心”，形成以下分工：

- **HUICHUAN-AI 控制平面**：保存实例清单、连接凭据、能力信息、状态快照、操作任务和审计记录。
- **New API / Sub2API 数据平面**：继续独立处理用户请求、渠道或上游账号调度、计费和本地运维。
- **适配器层**：屏蔽不同项目、不同版本的认证方式、接口路径和字段差异。
- **任务与巡检层**：定时拉取健康状态和聚合数据，并执行经过授权的远程操作。
- **项目瘦身**：删除 HUICHUAN-AI 中不再服务于控制平面的功能、代码、依赖、页面、任务和部署入口，最终不保留“以后也许会用”的死代码。

推荐按三个成熟度推进：

| 阶段 | 定位 | 主要能力 |
| --- | --- | --- |
| L1 统一观测 | 默认只读 | 实例纳管、健康巡检、版本识别、余额/用量/资源数量聚合、告警 |
| L2 受控运维 | 显式授权 | 启停资源、批量检测、刷新、远程升级触发、失败重试、操作审计 |
| L3 配置治理 | 按模板同步 | 配置基线、差异预览、定向下发、漂移检测、回滚 |

首个可交付版本应完成 L1，并只选择少量低风险操作进入 L2。用户、余额、订单和账单不在首版做跨实例双向同步。

## 1. 背景与问题

当 New API 和 Sub2API 实例增多后，日常管理通常出现以下问题：

1. 管理入口分散，需要反复登录不同后台。
2. 各实例健康状态、版本、余额、用量和资源数量缺少统一视图。
3. New API 的“渠道”和 Sub2API 的“上游账号”概念不同，无法直接使用同一套字段操作。
4. 批量变更依赖人工逐站执行，容易遗漏，也无法统一审计。
5. 上游项目持续更新，管理 API 和认证方式可能变化，直接耦合会导致升级后大面积失效。
6. 多实例写操作存在部分成功、重复执行和配置覆盖风险，需要任务化、幂等和回滚保护。

HUICHUAN-AI 已具备 Gin、GORM、React、权限目录、管理审计和带数据库租约的系统任务框架，可作为控制平面的实现基础。

## 2. 建设目标

### 2.1 目标

- 在一个后台统一管理多个 New API、HUICHUAN-AI 和 Sub2API 实例。
- 自动识别实例类型、版本、认证能力和可管理功能。
- 提供实例健康、延迟、版本、资源数量、用量与异常的聚合看板。
- 通过适配器隔离各项目接口差异，避免业务层到处判断实例类型。
- 所有远程写操作支持权限控制、执行前预览、幂等、超时、重试和审计。
- 支持标签、环境和分组，方便按生产、测试、区域或业务线批量筛选。
- 为后续配置模板、漂移检测和可选统一流量入口保留扩展点。
- 将 HUICHUAN-AI 从完整 AI 网关收缩为专用多实例管理平台，删除与该定位无关的本地业务模块。

### 2.2 非目标

首版明确不做：

- 不直接连接或修改远端实例数据库。
- 不把多个实例的用户、订单、支付回调和账单合并为一套强一致数据。
- 不自动跨实例搬运明文 API Key、OAuth Token 或用户密码。
- 不默认代理所有模型请求，避免控制平面成为业务流量单点。
- 不承诺适配任意魔改版本；未知版本先降级为基础健康检查。
- 不在未预览差异、未确认影响范围时自动覆盖远端配置。

## 3. 术语与边界

| 术语 | 含义 |
| --- | --- |
| 控制平面 | 当前二开的 HUICHUAN-AI，负责统一管理，不直接承担远端实例的业务数据权威 |
| 受管实例 | 被纳管的一个 New API、HUICHUAN-AI 或 Sub2API 部署 |
| 适配器 | 将统一管理协议转换为某类实例原生管理 API 的组件 |
| 能力 | 实例当前支持的具体管理动作，例如读取渠道、检测账号、触发升级 |
| 观测状态 | 从远端拉取并带时间戳保存的状态，只用于展示和判断 |
| 期望状态 | 管理员通过模板声明、希望远端最终达到的配置 |
| 漂移 | 观测状态与期望状态之间的差异 |
| 远程操作 | 会读取或修改受管实例的任务，例如同步清单、启用资源或触发检测 |

每个受管实例仍是自身用户、余额、资源和账单的唯一权威来源。控制平面只保存管理所需的元数据、聚合值和最小必要快照。

## 4. 用户角色与权限

沿用现有 Root、管理员和普通用户体系，并在 `authz` 中新增细粒度权限：

| 权限 | 建议默认角色 | 能力 |
| --- | --- | --- |
| `managed_instance.view` | 管理员、Root | 查看实例和脱敏状态 |
| `managed_instance.create` | Root | 新增实例和写入凭据 |
| `managed_instance.update` | Root | 修改地址、标签、巡检策略和凭据 |
| `managed_instance.delete` | Root | 删除纳管关系，不删除远端实例 |
| `managed_instance.operate` | 指定管理员、Root | 执行允许的单实例远程操作 |
| `managed_instance.batch_operate` | Root | 执行批量远程写操作 |
| `managed_instance.secret_rotate` | Root | 更换或撤销连接凭据 |
| `managed_instance.audit` | Root | 查看远程操作审计和详细错误 |
| `managed_template.view` | 指定管理员、Root | 查看配置模板和漂移 |
| `managed_template.apply` | Root | 应用模板和执行配置同步 |

普通用户不进入实例中心。管理员即使有查看权限，也不能读取密钥、密码、Cookie、完整请求头或远端敏感配置。

## 5. 功能范围

### 5.1 实例纳管

新增实例时录入：

- 名称、Base URL、实例类型（自动识别或手动指定）。
- 环境：`production`、`staging`、`development`。
- 标签：区域、业务线、负责人等自定义键值。
- 认证方式和凭据。
- 请求超时、巡检间隔、TLS 校验策略和可选出站代理。
- 管理模式：`observe`、`operate`、`enforce`。

保存前必须执行连接测试，返回：

- DNS、TCP、TLS 和 HTTP 分阶段结果。
- 识别到的产品、版本和认证模式。
- 可用能力列表。
- 服务端时间与控制平面时间偏差。
- 脱敏后的失败原因和建议动作。

### 5.2 统一总览

实例中心首页展示：

- 实例总数、在线、异常、离线、凭据失效和版本待升级数量。
- 按类型、环境、标签和状态筛选。
- 最近巡检时间、连续失败次数、HTTP 延迟和版本。
- 今日请求量、Token 用量、费用或额度等能够可靠获取的聚合指标。
- New API 渠道数量、启用数量和异常数量。
- Sub2API 上游账号数量、可用数量、限流或凭据异常数量。
- 最近失败操作和未处理告警。

聚合指标必须保留 `source_instance_id`、数据时间和采集状态，禁止把缺失数据展示为 `0`。

### 5.3 实例详情

详情页使用标签页组织：

| 标签页 | 内容 |
| --- | --- |
| 概览 | 健康、版本、延迟、核心资源数量、最近异常 |
| 资源 | 渠道、上游账号、用户、API Key、分组等适配器支持的只读清单 |
| 指标 | 请求、Token、费用、错误率和延迟趋势 |
| 配置差异 | 当前配置摘要、关联模板和漂移项 |
| 操作记录 | 任务进度、结果、操作者和审计信息 |
| 连接设置 | 地址、认证状态、巡检策略和凭据轮换；仅 Root 可见 |

不同实例没有的能力不显示空页面，前端依据能力清单决定标签和按钮。

### 5.4 受控操作

首批建议支持以下低风险操作：

- 立即巡检。
- 刷新资源清单。
- 执行渠道或上游账号连通性检测。
- 启用或停用指定资源。
- 重试上一次失败任务。

升级、批量删除、额度修改、用户状态修改和凭据分发属于高风险操作，应在后续阶段逐项开放，并增加二次确认、影响预览和更严格权限。

### 5.5 配置模板与漂移

模板不保存整份远端数据库，只管理明确白名单内的配置项，例如：

- 通用超时、重试和日志策略。
- 可公开的倍率或分组规则。
- 告警阈值。
- 指定资源的启停基线。

模板应用流程固定为：

```text
选择模板和目标实例
  -> 拉取最新状态
  -> 生成逐实例差异
  -> 管理员确认
  -> 创建远程操作任务
  -> 逐实例执行并验证
  -> 保存结果和回滚材料
```

同步模式：

| 模式 | 行为 |
| --- | --- |
| `disabled` | 不比较也不下发 |
| `audit` | 只检测并展示漂移，推荐默认值 |
| `enforce` | 经授权后按模板修正白名单配置 |

## 6. 总体架构

```text
管理员浏览器
    |
    v
HUICHUAN-AI Web / API
    |
    +-- 实例服务 -------- 实例、标签、能力、状态快照
    +-- 凭据服务 -------- 加密、轮换、脱敏
    +-- 操作服务 -------- 预览、幂等、任务、审计
    +-- 巡检调度器 ------ 周期任务、退避、告警
    |
    v
适配器注册表
    |
    +-- NewAPIAdapter
    +-- HuichuanAdapter
    +-- Sub2APIAdapter
    +-- GenericHealthAdapter
           |
           v
     HTTPS 管理 API
           |
           +-- New API 实例 A/B/C
           +-- Sub2API 实例 D/E/F
```

### 6.1 为什么不复用“渠道”模型

渠道表示模型请求的上游路由目标；受管实例表示需要巡检、读取和运维的完整系统。两者生命周期、凭据、权限和统计口径均不同。将实例存入渠道会导致以下问题：

- 无法表达一个实例内部的多个渠道或账号。
- 管理凭据与模型调用 Key 混用。
- 删除、禁用和健康检测语义冲突。
- 后续配置同步和审计难以扩展。

因此必须新增独立领域模型。

### 6.2 控制平面不承载业务流量

MVP 中，客户端仍直接访问各数据平面或既有统一网关。控制平面故障只影响管理视图和远程操作，不影响正在发生的模型请求。

若后续需要一个统一 API 地址，应独立设计“联邦路由”模块，并使用健康快照选择实例；该能力不与实例管理 MVP 混合交付。

## 7. 适配器设计

### 7.1 统一接口

后端定义稳定的内部接口，业务服务只依赖接口，不直接调用某项目的 URL：

```go
type InstanceAdapter interface {
    Kind() InstanceKind
    Identify(ctx context.Context, client *Client) (*Identity, error)
    Capabilities(ctx context.Context, client *Client) ([]Capability, error)
    Health(ctx context.Context, client *Client) (*Health, error)
    Summary(ctx context.Context, client *Client, window TimeWindow) (*Summary, error)
    Inventory(ctx context.Context, client *Client, resource ResourceKind, cursor string) (*Page, error)
    Plan(ctx context.Context, client *Client, action Action) (*ChangePlan, error)
    Execute(ctx context.Context, client *Client, action Action, idempotencyKey string) (*ActionResult, error)
}
```

`Plan` 与 `Execute` 分离。任何写操作先返回影响对象、变更前后摘要、风险级别和是否可回滚，再允许创建执行任务。

### 7.2 实例识别

识别顺序：

1. 请求通用健康和状态端点，例如 `/api/status` 或 `/health`。
2. 根据响应头、响应结构和版本字段生成产品指纹。
3. 使用用户指定类型校验指纹，防止误连到其他服务。
4. 认证后探测能力，不只根据产品名假设接口一定存在。
5. 未知版本降级为 `GenericHealthAdapter`，只保留基础巡检。

不要仅依赖一个固定 Header。New API 新旧版本、HUICHUAN-AI 分支和 Sub2API 的认证协议可能不同，适配器应将认证方式作为版本化能力处理。

### 7.3 认证策略

优先级建议：

1. 受管实例签发的专用服务账号或长期管理 Token。
2. 原生个人访问令牌或 Admin Token。
3. 短期登录 Token + 可轮换刷新凭据。
4. Session Cookie 仅作为兼容方案，不作为推荐生产配置。

New API 适配器需兼容新版 Bearer PAT 与旧分支可能要求的用户标识 Header；HUICHUAN-AI 当前分支使用 `HUICHUAN-User`，不能硬编码为所有 New API 都一致。Sub2API 适配器使用其 `/api/v1/admin` 管理接口和对应 Token，并在 Token 过期时返回明确的 `credential_expired`，不得静默改用用户名密码反复登录。

### 7.4 能力标识

能力使用稳定字符串，示例：

```text
health.read
version.read
metrics.summary.read
channels.list
channels.test
channels.toggle
accounts.list
accounts.test
accounts.toggle
users.summary.read
keys.summary.read
system.update.plan
system.update.execute
```

前端按钮、权限判断和任务创建均以能力为准。版本不支持时返回 `unsupported_capability`，不通过字符串匹配错误消息猜测。

### 7.5 统一错误模型

适配器将远端错误转换为：

| 错误码 | 含义 | 是否重试 |
| --- | --- | --- |
| `dns_failed` | 域名解析失败 | 是，退避 |
| `connect_timeout` | TCP 或代理连接超时 | 是，退避 |
| `tls_failed` | TLS 校验失败 | 否，需处理证书 |
| `authentication_failed` | 凭据错误 | 否 |
| `credential_expired` | 凭据过期 | 否，需轮换 |
| `permission_denied` | 远端账号权限不足 | 否 |
| `rate_limited` | 远端限流 | 是，遵循 `Retry-After` |
| `unsupported_version` | 版本不兼容 | 否，降级能力 |
| `unsupported_capability` | 不支持该操作 | 否 |
| `remote_conflict` | 远端状态已变化 | 否，重新生成计划 |
| `remote_internal` | 远端内部错误 | 有限重试 |
| `invalid_response` | 响应结构不符合契约 | 否，标记适配异常 |

错误详情保存时必须移除 Authorization、Cookie、Token、密码、完整 DSN 和响应中的敏感字段。

## 8. 数据模型

### 8.1 `managed_instances`

实例主表：

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `name` | 唯一显示名称 |
| `kind` | `new_api`、`huichuan`、`sub2api`、`generic` |
| `base_url` | 规范化后的 HTTPS 地址 |
| `environment` | 环境 |
| `labels` | 标签 JSON |
| `management_mode` | `observe`、`operate`、`enforce` |
| `status` | `unknown`、`healthy`、`degraded`、`offline`、`auth_failed` |
| `version` | 最近识别版本 |
| `capabilities` | 最近能力清单 JSON |
| `tls_verify` | 是否校验证书；生产默认必须为 `true` |
| `request_timeout_seconds` | 单次管理请求超时 |
| `check_interval_seconds` | 巡检间隔 |
| `last_seen_at` | 最近成功访问时间 |
| `last_checked_at` | 最近巡检时间 |
| `consecutive_failures` | 连续失败次数 |
| `created_by` / `updated_by` | 操作人 |
| `created_at` / `updated_at` | 时间戳 |

`base_url` 只允许 `http` 或 `https`，保存时移除末尾 `/`，禁止包含查询参数、片段和用户信息。

### 8.2 `managed_instance_credentials`

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `instance_id` | 实例 ID，唯一有效凭据 |
| `auth_type` | `bearer_pat`、`admin_token`、`session_compat` 等 |
| `ciphertext` | 加密后的凭据包 |
| `key_version` | 主密钥版本 |
| `fingerprint` | 不可逆摘要，用于识别是否更换 |
| `expires_at` | 可选过期时间 |
| `last_verified_at` | 最近验证成功时间 |
| `rotated_by` / `rotated_at` | 轮换审计 |

API 永不返回 `ciphertext`。凭据写入成功后的响应只包含认证类型、指纹后四位、过期时间和最近验证时间。

### 8.3 `managed_instance_snapshots`

保存最近一次资源与配置摘要，不保存明文密钥或完整用户隐私数据：

- `instance_id`
- `snapshot_type`
- `schema_version`
- `observed_at`
- `etag` 或内容摘要
- `payload`
- `collection_status`
- `error_code`

高频指标不无限写入该表。趋势数据使用按小时聚合和保留策略，或后续接入专用时序数据库。

### 8.4 `managed_instance_operations`

远程操作任务的业务记录：

- 操作 ID、任务 ID、实例 ID、动作和风险级别。
- 幂等键、期望版本或 ETag。
- 变更计划、脱敏参数、执行状态和进度。
- 执行前摘要、执行后摘要和回滚材料。
- 操作人、审批人、开始时间、完成时间和错误码。

批量操作创建一条父记录，并为每个目标实例创建子记录。这样可以准确表达“8 个成功、2 个失败”，而不是把批量任务压成一个状态。

### 8.5 `managed_instance_audits`

记录以下事件：

- 新增、修改、删除纳管关系。
- 凭据创建、验证、轮换和撤销。
- 查看敏感管理详情。
- 创建、确认、取消和重试远程操作。
- 应用模板和修改自动同步策略。

审计记录不保存凭据、完整远端响应或用户隐私正文。

## 9. 管理 API 草案

统一使用 `/api/managed-instances` 命名空间：

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |

## 10. 巡检、任务与并发

### 10.1 巡检策略

建议默认值：

| 项目 | 默认值 |
| --- | --- |
| 健康巡检 | 60 秒 |
| 资源摘要同步 | 5 分钟 |
| 指标聚合 | 5 分钟 |
| 版本与能力刷新 | 6 小时 |
| 单次请求超时 | 10 秒 |
| 连续失败告警 | 3 次 |
| 恢复通知 | 首次成功后立即发送 |

所有周期增加 0% 至 20% 随机抖动，避免大量实例同时请求。失败后使用指数退避，认证失败和不支持版本不做高频自动重试。

### 10.2 复用现有系统任务

现有 `SystemTask` 已提供任务状态、数据库租约和多节点执行保护，可复用其生命周期，但需要补充“作用域锁”：

- 新任务类型：`managed_instance_probe`、`managed_instance_sync`、`managed_instance_action`。
- 同一实例同类写操作串行，不同实例允许有限并发。
- 锁键使用 `task_type + instance_id`，不能继续只按任务类型全局串行。
- 全局设置最大并发和每实例最大并发，防止拖垮控制平面或受管实例。
- Worker 必须响应 `context.Context` 取消，并在租约丢失后停止提交结果。

如果直接沿用当前仅按 `Type` 加锁的实现，多实例同步会被不必要地串行化；该处是实现阶段需要优先改造的基础能力。

### 10.3 幂等与冲突

- 每次写操作生成控制平面幂等键，并在远端支持时透传。
- 本地以 `instance_id + action + idempotency_key` 建唯一约束。
- 计划中保存远端资源版本、ETag 或内容摘要。
- 执行前再次读取远端状态；已变化则返回 `remote_conflict`，不盲目覆盖。
- 网络超时但结果未知时，先查询远端状态再决定是否重试。
- 批量操作不做数据库式“跨实例事务”承诺，使用逐实例结果和补偿操作表达最终状态。

## 11. 安全设计

### 11.1 凭据保护

- 使用独立主密钥对凭据做带随机 nonce 的认证加密，并支持 `key_version` 轮换。
- 主密钥只从环境变量或外部密钥管理系统注入，不写入数据库和日志。
- 数据库仅保存密文和不可逆指纹。
- 凭据只在单次请求所需的最短时间内解密，不进入缓存、任务 Payload 或错误信息。
- 前端提交凭据后立即清空表单状态，任何读取接口均不回显。

### 11.2 SSRF 与网络边界

实例地址由 Root 配置，仍需防止服务端请求伪造：

- 仅允许 `http`、`https`，生产实例默认强制 HTTPS。
- 禁止 URL 用户信息、非预期重定向和跨主机重定向。
- DNS 解析后校验目标 IP；私网、回环和链路本地地址需要显式出站策略授权。
- 每次重定向和连接前重新校验，降低 DNS rebinding 风险。
- 配置允许的域名、CIDR 和端口范围。
- 响应体设置大小上限，避免异常接口占满内存。
- 管理请求使用独立 HTTP Client、连接池、代理和超时，不复用模型转发客户端。

### 11.3 远程写保护

- 实例默认 `observe`，新增后不会自动获得写权限。
- `operate` 和 `enforce` 必须由 Root 显式开启。
- 批量写操作必须展示目标数量、变更摘要和不可回滚项。
- 高风险操作要求二次验证，并禁止在同一请求中完成“生成计划 + 执行”。
- 删除纳管关系只删除本地管理数据，不调用远端删除接口。
- 管理写请求统一携带控制平面请求 ID，方便两端日志关联。

## 14. HUICHUAN-AI 瘦身与删除方案

### 14.1 最终形态

瘦身完成后，当前仓库只承担以下职责：

- 管理员身份认证、Root 初始化和最小管理员账号管理。
- RBAC 权限、管理审计和安全中间件。
- 受管实例、凭据、适配器、巡检、聚合指标和远程操作。
- 系统任务、多节点租约、告警通知、系统信息和在线升级。
- 控制平面设置、数据库迁移、日志、i18n 和默认管理前端。
- 控制平面的 Docker、Compose、systemd 和发布构建。

控制平面不再提供本地模型中转、用户售卖、充值计费、聊天或数据采集能力。需要这些能力时，由受管的 New API 或 Sub2API 实例提供。

### 14.2 保留和改造清单

| 现有能力 | 处理方式 | 最终用途 |
| --- | --- | --- |
| Setup 与 Root 初始化 | 保留并简化 | 首次创建控制平面 Root |
| 用户与登录 | 收缩 | 只保留 Root、管理员、会话、2FA/Passkey 和必要 SSO |
| `authz` 权限体系 | 保留并扩展 | 实例查看、操作、凭据和模板权限 |
| 管理审计 | 保留并扩展 | 记录纳管、凭据和远程操作 |
| `SystemTask` 与数据库租约 | 保留并改造 | 多实例巡检、同步和操作任务 |
| 系统信息与在线升级 | 保留 | 控制平面自身运维 |
| 邮件、告警与日志基础设施 | 保留并收缩 | 实例离线、恢复、凭据和任务告警 |
| GORM、配置与 Option | 保留并清理 | 控制平面数据和设置 |
| `web/default` 基础布局 | 保留并重构 | 实例中心管理界面 |
| 代理能力 | 替换 | 删除渠道代理池，新增最小化的实例管理出站代理配置 |
| 统计图表与表格组件 | 按依赖保留 | 实例指标和资源清单 |

“用户与登录收缩”表示管理员仍是本地用户，但删除普通用户额度、钱包、令牌和商业化字段的业务入口。为减少高风险数据库改动，首版可以保留尚被鉴权依赖的列，待鉴权模型稳定后再迁移。

### 14.3 删除清单

以下模块与专用控制平面无关，纳入最终删除范围：

| 模块 | 删除内容 | 替代方式 |
| --- | --- | --- |
| 本地模型中转 | `/v1`、Claude、Gemini、Realtime、图片、音频、视频等 Relay 路由与供应商适配代码 | 模型请求继续访问受管实例 |
| 本地渠道与路由 | 本地渠道 CRUD、渠道测试、模型映射、倍率、亲和、重试和本地负载均衡 | 通过实例适配器读取和管理远端渠道/账号 |
| 本地 API Key | Token/Key 创建、额度、模型限制和使用查询 | Key 由各受管实例维护，控制平面只显示脱敏摘要 |
| 本地计费商业化 | 钱包、充值、支付、兑换码、订阅、套餐、订单和账单 | 由受管实例独立处理 |
| 本地用量日志 | 本地模型消费日志、计价快照、导出和渠道请求统计 | 只聚合远端实例提供的统计，不保存本地 Relay 日志 |
| 数据快照 | Dataset Capture、Capture Proxy、快照导出和访问邮件 | 不再经过本地模型流量，因此整体删除 |
| 聊天与调试 | Chat、Playground、本地模型列表和调用测试页 | 实例中心只保留管理 API 的连通性测试 |
| 异步模型任务 | Midjourney、Suno、视频、部署任务和供应商轮询 | 由受管实例执行 |
| 本地代理池 | 渠道代理组、切换、日志分析、恢复测试和渠道绑定 | 新建独立的 Connector 出站代理，禁止复用渠道语义 |
| 公共门户 | 首页营销内容、价格页、榜单、钱包和普通用户自助页 | 登录后直接进入实例中心 |
| 普通用户注册 | 公开注册、邮箱注册、面向普通用户的 OAuth 绑定和找回流程 | 默认关闭，只允许 Root 创建管理员；可保留管理员 SSO |
| 实验与无关集成 | NERV 目录、相关设置页面、目录同步和实验内容 | 整体删除 |
| 旧前端 | `web/classic` 及其兼容路由、组件和构建入口 | 只保留 `web/default` |
| 桌面壳 | `electron` 打包与桌面专用脚本 | 默认删除；控制平面使用 Web 部署 |
| 独立采集命令 | `cmd/dataset-capture-proxy`、Capture Proxy Docker 文件和服务入口 | 无替代，直接删除 |

以上是按业务模块定义的最终范围，不等于直接按目录整块删除。例如 `service`、`model`、`dto` 中存在交叉依赖，必须先做引用图，再删除其中属于旧业务的文件。

### 14.4 删除顺序

删除按以下顺序执行，每一步均要求项目仍可构建：

1. **建立基线**：记录现有路由、后台任务、数据库表、环境变量、前端页面、构建产物和依赖。
2. **冻结旧功能**：停止为待删除模块增加功能，关闭公开注册和新商业化数据写入。
3. **先建控制平面闭环**：完成管理员登录、实例 CRUD、凭据、巡检和实例中心首页，确保删除旧首页后仍可使用。
4. **下线入口**：删除前端菜单、路由和后端 API 注册，不再启动对应定时任务。
5. **删除业务代码**：按“前端 -> Controller/Router -> Service -> Model”的依赖方向逐组删除。
6. **删除 Relay 核心**：确认控制平面没有模型流量后，删除协议转换、供应商适配器和本地渠道链路。
7. **删除依赖与资产**：清理 `go.mod`、前端依赖、环境变量、Docker 文件、脚本、翻译、图标和文档。
8. **处理数据库遗留**：先归档，再通过显式维护命令删除旧表和旧列；普通启动不得静默执行破坏性迁移。
9. **全仓验证**：检查死路由、死翻译键、未使用导出、二进制体积、镜像内容和许可证清单。

### 14.5 数据清理策略

“删除没有用的功能”最终也包含旧业务数据，但数据删除必须可控：

- 新安装只创建控制平面需要的表，不再 AutoMigrate 旧业务模型。
- 已有安装先生成旧表、行数、文件目录和占用空间清单。
- 提供一次性归档工具，将用户余额、订单、日志、快照和关键配置导出并生成 SHA-256。
- 归档完成后，由 Root 显式执行 `legacy-data purge` 类维护命令；不在升级启动时自动删表或删文件。
- 清理命令必须支持 `--dry-run`，展示将删除的表、目录、行数和预计空间。
- 删除前再次校验目标路径位于应用数据目录内，数据库必须匹配当前控制平面实例标识。
- 审计记录、管理员账号、权限、系统任务和新实例管理数据不进入旧数据清理范围。

### 14.6 不保留兼容壳

瘦身完成后不长期保留以下形式的死代码：

- 只返回“功能已下线”的旧业务 Controller。
- 永久关闭但仍参与构建的 Feature Flag 分支。
- 未注册路由但仍被 AutoMigrate 的旧 Model。
- 不再使用却仍保留在镜像中的前端页面、供应商 SDK 和脚本。
- 为旧前端保留的兼容 API。

过渡版本可以短期返回 `410 Gone` 并给出迁移说明，但下一主版本应彻底删除路由与实现。

### 14.7 瘦身验收标准

1. 未登录只保留 Setup、登录、健康检查和必要静态资源入口。
2. 登录后第一屏为实例中心，不再出现渠道、令牌、钱包、充值、订阅、聊天和本地日志菜单。
3. 控制平面不注册任何模型 Relay 路由，也不接收用户模型 API Key。
4. 启动时不注册旧业务 Worker，不创建新的旧业务表。
5. `web/classic`、Electron、Capture Proxy、NERV 和无关 Docker 入口已删除。
6. `go.mod` 和前端依赖中不再存在仅由已删除供应商或商业化模块使用的包。
7. 全仓静态搜索不存在旧菜单、旧路由和已删除任务类型的有效引用。
8. Go 测试、前端类型检查、Lint、格式检查和生产构建全部通过。
9. 使用全新空数据库可完成 Setup、登录、添加三类实例和巡检。
10. 使用旧数据库升级时不会自动丢失数据，并可通过显式工具完成归档与清理。

### Phase 1：控制平面骨架与第一轮瘦身

- 数据表、加密凭据、权限和审计。
- 新增、测试、编辑、删除纳管关系。
- 产品识别、能力探测、健康巡检和退避。
- 统一总览、实例列表、详情概览。
- 聚合资源数量和基础指标。
- 凭据失效、离线和恢复告警。
- 删除公共首页、价格、榜单、钱包、充值、订阅、兑换码、聊天和 Playground 的前后端入口。
- 默认关闭普通用户注册，登录后直接进入实例中心。

交付物：可稳定纳管并观测多个实例，且不再暴露无关用户与商业化功能的 L1 版本。

### Phase 2：网关链路删除与受控操作

- 操作计划、幂等键、冲突检测和逐实例状态。
- 手动检测、资源启停和失败重试。
- 批量计划与批量执行。
- 任务中心和完整操作审计。
- 删除本地 Relay、渠道、Token、倍率、模型、用量日志、数据快照和异步模型任务。
- 删除渠道代理池，完成实例 Connector 出站代理替代。
- 清理仅由上述模块使用的 Go/前端依赖、环境变量和定时任务。

交付物：专用控制平面形态、默认关闭写能力、可按实例授权的 L2 版本。

### Phase 3：遗留清理与配置治理

- 配置模板、白名单字段和版本化 Schema。
- 漂移检测、差异预览和定向应用。
- 应用后验证、补偿操作和回滚材料。
- 删除旧前端、Electron、Capture Proxy、NERV、无关构建入口和文档。
- 提供旧业务数据清单、归档、`dry-run` 和显式清理工具。
- 新安装停止创建全部旧业务表。

交付物：无长期兼容壳、以 `audit` 为默认模式的精简 L3 版本。

### Phase 4：可选联邦路由

- 统一入口和实例级流量策略。
- 基于健康、容量、费用和区域的实例选择。
- 熔断、故障转移、粘性会话和全链路日志。

该阶段需要独立设计与压测，不属于本轮管理平台二开的默认范围。

## 16. 测试策略

### 16.1 单元测试

- URL 规范化、SSRF 校验和重定向校验。
- 凭据加密、解密、轮换和脱敏。
- 各适配器响应解析、分页、能力识别和错误映射。
- 巡检状态机、退避、恢复和告警去重。
- 计划/执行分离、幂等和冲突检测。
- 权限目录和远程写鉴权。

### 16.2 契约测试

每个适配器至少覆盖：

- 最低支持版本、当前推荐版本和一个未知版本。
- 正常、401、403、404、429、500、超时和非法 JSON。
- 分页边界、空列表和字段新增。
- 凭据过期与权限不足。
- 接口成功但业务 `success=false` 的响应。

### 16.3 集成测试

使用 Docker Compose 启动以下矩阵：

- HUICHUAN-AI 控制平面。
- 一个 New API 受管实例。
- 一个 HUICHUAN-AI 受管实例。
- 一个 Sub2API 受管实例及其 PostgreSQL、Redis。
- 可注入延迟、断连、429 和错误响应的测试代理。

验证多实例并发巡检、控制平面重启、任务租约转移、凭据轮换和部分成功的批量操作。

### 16.4 前端测试

- 桌面与移动宽度下表格、筛选、抽屉和任务进度无重叠。
- 无权限、无能力、加载中、空数据、部分失败和离线状态完整。
- 所有危险操作均经过计划预览和确认。
- 密钥字段不会被查询缓存、错误提示或浏览器日志回显。

### 16.5 瘦身回归测试

- 对全部已删除 HTTP 路径执行路由枚举，确认不再注册；过渡期明确要求的路径除外。
- 检查启动日志和任务注册表，确认旧业务 Worker 不再启动。
- 使用全新数据库启动，确认只创建控制平面表。
- 使用旧数据库升级，确认不会自动删表；归档和清理工具分别覆盖 `dry-run`、成功、失败与中断恢复。
- 对 Go 和前端执行未使用代码、未使用依赖、死翻译键和循环依赖检查。
- 解包发布二进制与容器镜像，确认不再包含旧前端、Electron、NERV、Capture Proxy 和无关脚本资产。
- 验证控制平面不监听模型 Relay 路由，不接受模型 API Key，也不会启动供应商后台轮询。

## 17. 验收标准

只读 MVP 完成时必须满足：

1. 可纳管至少 20 个混合类型实例，巡检不会阻塞模型请求主链路。
2. 能正确区分 New API、HUICHUAN-AI、Sub2API 和未知服务。
3. 单个实例故障不会影响其他实例采集。
4. 控制平面重启后实例、状态、任务和审计可恢复。
5. 凭据在数据库、API、日志、审计和前端中均不以明文出现。
6. 未授权管理员无法新增实例、轮换凭据或执行远程写操作。
7. 所有聚合数据都标记来源实例和采集时间，缺失值不伪装为零。
8. 未知或不支持版本自动降级，不导致任务 Worker 崩溃。
9. 巡检任务具有并发上限、超时、抖动、退避和租约保护。
10. 删除纳管关系不会删除或停用任何远端资源。
11. Go 定向测试、前端类型检查和生产构建通过。
12. 关键页面通过桌面和移动端截图检查。
13. 本地网关、商业化、聊天、快照、旧前端和实验模块已按第 14 节验收标准删除。

## 18. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 上游管理 API 变更 | 适配器失效 | 能力探测、版本矩阵、Fixture 契约测试、未知版本降级 |
| 管理 Token 权限过大 | 远端被误操作 | 专用账号、最小权限、加密、默认只读、轮换和审计 |
| 批量操作部分成功 | 状态不一致 | 父子任务、逐实例结果、幂等、补偿操作，不宣称跨实例事务 |
| 高频采集拖垮实例 | 业务延迟 | 独立客户端、并发上限、抖动、退避、响应大小限制 |
| 指标口径不同 | 聚合误导 | 保留原始口径和来源，只对可比指标求和 |
| 私网实例引入 SSRF | 控制平面网络风险 | Root 专属配置、出站 allowlist、逐跳校验和审计 |
| 控制平面数据库增长 | 查询变慢 | 只存摘要、小时聚合、保留与清理策略 |
| 把管理平台变成流量单点 | 全部调用受影响 | MVP 管理流量与模型业务流量分离 |
| 删除旧模块破坏共享基础设施 | 控制平面无法启动 | 先做引用图和替代闭环，每组删除后构建与测试 |
| 自动清理旧数据 | 不可恢复的数据损失 | 启动迁移不删表，归档后由 Root 显式执行清理 |
| 为兼容长期保留死代码 | 体积和维护成本继续增长 | 兼容仅限过渡版本，下一主版本彻底移除 |

## 19. 需要确认的产品决策

以下项目不阻塞只读 MVP，但应在进入 Phase 2 前确认：

| 决策 | 推荐默认值 |
| --- | --- |
| “管理”是否包含统一模型 API 入口 | 首版不包含，作为 Phase 4 独立设计 |
| 首批正式支持的版本 | 当前生产使用版本 + 各项目最新稳定版 |
| 是否允许保存登录密码自动换 Token | 不允许，优先专用长期 Token |
| 是否同步用户和余额 | 首版不做；后续仅支持明确的单向迁移任务 |
| 是否允许自动远程升级 | 首版只提示版本；Phase 2 后单独授权 |
| 配置同步默认模式 | `audit`，只报告漂移 |
| 私网地址是否允许纳管 | 允许，但必须命中 Root 配置的出站 allowlist |
| 数据保留 | 操作审计长期保留，分钟级指标短期保留并转小时聚合 |
| 旧业务数据何时删除 | 新控制平面验收后，先归档，再显式清理 |
| Electron 与旧前端是否保留 | 不保留，统一使用 `web/default` |

## 20. 推荐的首轮开发切片

第一轮代码只实现以下闭环：

1. `managed_instances`、加密凭据和最小审计表。
2. `NewAPIAdapter`、`HuichuanAdapter`、`Sub2APIAdapter` 的识别、健康和版本能力。
3. 实例新增前探测、CRUD、立即巡检和周期巡检。
4. 实例列表、详情概览、状态筛选和凭据轮换。
5. 离线、认证失败和恢复状态，不接远程写操作。
6. 单元测试、适配器 Fixture 和三类实例的集成验证。
7. 删除公共首页、价格、榜单、钱包、充值、订阅、兑换码、聊天和 Playground 入口。
8. 输出下一轮要删除的 Relay、渠道、Token、日志和快照依赖图。

该切片能够尽早验证最不确定的接口兼容与认证问题，同时不会把用户同步、批量写操作和统一流量入口的风险带入基础架构。
